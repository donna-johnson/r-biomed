Guide to R 00: Start-up and troubleshooting

R for Biomedical Science · Leeds Beckett University

This guide provides a structured routine to follow at the beginning of every data analysis session, taking you from opening R through to having a dataset that is clean, consistent, and ready for statistical testing. In practice, most analytical problems don’t arise from the statistical methods themselves but from issues such as files being loaded from the wrong location, variables being stored in the wrong format, inconsistent category labels, hidden missing values, or parts of the environment not being properly initialised. Working through the same sequence of checks each time helps you detect these problems early, reduces time spent trying to diagnose errors later, and supports a reproducible workflow in which your results can be repeated and justified.

There is also a troubleshooting guide at the end. The start-up checks help you prevent common problems before they occur, while the troubleshooting guide helps you interpret error messages and identify what has gone wrong when something doesn’t run as expected. Together they form a complete workflow: first you confirm that your data and environment are correct, and then, if an error still occurs, you have a clear process for diagnosing and fixing it. By the end of these steps you should be confident that you are analysing the correct dataset, that your variables are in the appropriate format for your chosen method, and that you have the information required to answer your research question in a transparent and reproducible way.

The examples use the tidyverse and assume your data is in an object called data, with made-up column names (sex, age, group and so on). Replace them with your own.

Start-up and data checking

What to do Example R code What you are checking / fixing
Open your project Double-click the .Rproj file R is looking in the project folder
Start with a clean session Session › Restart R (Ctrl + Shift + F10) No old objects affecting results
Load required packages library(tidyverse) All required tools are available
Check package versions (if work must match previous sessions) sessionInfo() You are using the same package environment
Check the data file is there list.files("data") The file name is correct and visible
Import the data data <- read_csv("data/data.csv") Data loads without errors. Read the message: it lists the type R has given each column.
Check dataset size dim(data) Row and column numbers are as expected
Confirm expected sample size nrow(data) Data have not been accidentally filtered
Preview the data head(data) Correct file and sensible layout
Check structure glimpse(data) Variable types are correct
Check variable names names(data) No unexpected spelling or spaces
Get a quick summary summary(data) Values are in realistic ranges
Check missing values colSums(is.na(data)) Identify where data are missing
Count duplicated rows (if relevant) sum(duplicated(data)) Each observation is unique if required

Cleaning and standardising variables

What to do Example R code What you are fixing
Standardise text to lower case data <- data |> mutate(sex = str_to_lower(sex)) Makes F, f, Female consistent
Remove extra spaces data <- data |> mutate(sex = str_trim(sex)) Fixes hidden spaces
Recode several labels into one category each data <- data |> mutate(sex = case_when(sex %in% c("f", "female") ~ "female", sex %in% c("m", "male") ~ "male", .default = sex)) Combines duplicate categories, leaving anything unexpected unchanged so you can spot it
Check the result count(data, sex) Confirms categories are correct
Convert to factor data <- data |> mutate(sex = factor(sex)) Makes variable usable in analysis
Convert numbers stored as text data <- data |> mutate(age = as.numeric(age)) Numbers stored as text (R warns if any value can’t be converted)
Convert grouping variables to factors data <- data |> mutate(group = factor(group)) Correct statistical handling
Give numeric group codes labels data <- data |> mutate(group = factor(group, levels = c(1, 2), labels = c("control", "treatment"))) Makes output interpretable

Handling missing or impossible values

What to do Example R code What you are fixing
Turn placeholder codes into NA data <- data |> mutate(bmi = na_if(bmi, 999)) Removes placeholder values
Remove rows with a missing key outcome (if required) data <- data |> drop_na(outcome) Keeps analysable cases
Check again for missing data colSums(is.na(data)) Confirms the change worked
Check minimum and maximum summary(data$age) Detects impossible values
Filter unrealistic values (example) data <- data |> filter(age >= 18, age <= 100) Applies study criteria

Validating variables for analysis

What to do Example R code What you are checking
Check group sizes count(data, group) Groups are not empty or too small
Check continuous variables are truly continuous n_distinct(data$age) Not accidentally categorical
Check distributions ggplot(data, aes(x = bmi)) + geom_histogram() Skew, unusual patterns, or errors
Quick outlier check ggplot(data, aes(y = bmi)) + geom_boxplot() Extreme values
Check factor reference level (for regression) data <- data |> mutate(group = fct_relevel(group, "control")) Correct interpretation of coefficients

Checking dates and special formats

What to do Example R code What you are fixing
Convert text to date format (day/month/year) data <- data |> mutate(date = dmy(date)) Dates stored correctly
Check date structure glimpse(data) Ready for time-based analysis
Look for non-numeric symbols in numeric fields distinct(data, cholesterol) Detects entries such as “>5”

Checking logical consistency

What to do Example R code What you are checking
Check impossible combinations filter(data, sex == "male", pregnant == "yes") Biologically impossible data
Check time variables are valid filter(data, time < 0) No negative follow-up time

Creating analysis-ready variables

What to do Example R code What you are checking
Create derived variable data <- data |> mutate(bmi_cat = if_else(bmi >= 30, "obese", "non_obese")) Variables needed for analysis exist
Check new variable count(data, bmi_cat) Created correctly

Final confirmation

What to do Example R code What you are checking
Check structure again glimpse(data) All variables in correct format
Re-run summary summary(data) Cleaned data look sensible
Quick visual linked to research question ggplot(data, aes(x = group, y = outcome)) + geom_boxplot() Data are ready for the planned test
Confirm you have the required variables for your research question (no specific code) Your analysis is actually possible

Troubleshooting

Issue / error message Try / check this
Object not found This almost always means the object hasn’t been created in the current session or its name doesn’t exactly match. R is case sensitive, so data, Data and DATA are different. Run the line where the object is created, check the spelling, and use ls() to see what objects actually exist in the environment.
Could not find function (e.g. "read_csv" or "ggplot") The package that contains the function hasn’t been loaded in this session. Run library(tidyverse), and make sure it is at the top of your script or workbook.
There is no package called… The package isn’t installed on this computer. Install it once, in the Console: install.packages("tidyverse").
I ran the script but nothing happened R only executes the lines you send to the console. Highlight the code and press Run, or place the cursor on the line and use the run shortcut (Ctrl + Enter). Just opening a script does not execute it.
The function worked yesterday but not today The session has been restarted and required packages have not been loaded. Re-run the library() calls at the top of the script, for example library(tidyverse). In a reproducible script, package loading should always be included at the beginning.
Cannot find the file / does not exist in current working directory R looks for files relative to the working directory. Check that you have opened your project (its name shows at the top right of RStudio), then confirm the file is where your code says it is with list.files() or list.files("data"). The fix is usually to move the file into the project, or correct the path in your code, rather than calling setwd().
The file is in my folder but R still cannot see it Check the exact file name and extension. Windows may hide extensions, so what looks like data might actually be data.csv.csv. Use list.files() to see the true name and match it exactly in the code.
Unexpected symbol or unexpected input This usually means a missing quote, bracket, or comma on the previous line. R often flags the error where it notices the problem, not where it started. Check the line above for unclosed quotes (" " or ' '), brackets ( ) or braces { }.
My column name does not work in the code Column names must match exactly. Use names(data) to inspect them. If they contain spaces or special characters, either wrap them in backticks (`Blood Pressure`) or rename them with rename() or janitor::clean_names().
filter() error mentioning a “named input” You have used = where you meant ==, e.g. filter(dose = 2). Use two equals signs to test whether values are equal.
ggplot error suggesting you used |> or %>% instead of + The layers of a ggplot are joined with +, not with the pipe.
I created the object but it has disappeared You may have restarted the session, cleared the environment, or run only part of the script. In a good workflow the script should run from top to bottom without relying on previously created objects.
I ran a dplyr step but the data hasn’t changed filter(), mutate() and friends return a new tibble; they don’t change the original. To keep the result, assign it: data <- data |> mutate(...).
The output looks wrong after I imported the data Check the structure with glimpse(data), and re-read read_csv()’s message. The most common issue is a numeric variable being read as character because of non-numeric entries such as text (“High”, “<5”) or missing-value codes.
Numbers are being treated as text This happens when a column contains non-numeric characters. Use as.numeric() or parse_number() once you have decided what to do with the non-numeric entries, or tell read_csv() which codes mean “missing” with its na = argument, e.g. read_csv("data/data.csv", na = c("", "NA", "999")).
Package is installed but the function is not found Installing a package is not the same as loading it. You still need library(package_name) in the script.
There is a red plus sign in the console and R will not run R is waiting for you to finish the command. This likely means a bracket or quote hasn’t been closed. Press Esc to break out, then fix the incomplete line.
My script works line by line but not when I run it all at once This indicates the script depends on objects created interactively or in the wrong order. Reorganise the script so that data import, cleaning, and analysis occur in a logical sequence and the environment starts empty.
I saved the script but the changes are not reflected Saving the script does not re-run it. The updated code must be executed again.
My Quarto document won’t render, but every chunk ran fine interactively Rendering starts R from scratch and runs the document from top to bottom. Something the document needs was only ever created in the Console (often a library() call). Restart R, then use Run All to find the first chunk that fails.
