Week 2, session 1: before the session

Finding and fixing messy data, tried out in your browser

Real data is rarely ready to analyse. The same category gets typed three different ways, numbers arrive with units stuck to them, someone writes 999 to mean “no result”, and the measurements are laid out in whatever shape suited the spreadsheet rather than the analysis. In session 1 you’ll take a messy dataset from a diabetes trial and get it into shape. This page introduces the four tools you’ll use most:

  • count(), to find problems;
  • case_when(), to fix inconsistent categories;
  • NA and na.rm = TRUE, to deal with missing values; and
  • pivot_longer(), to change the shape of a table.
NoteThis page takes a little longer to start

As well as starting R, your browser needs to download the dplyr and tidyr packages. Give it up to a minute the first time. The box below loads them and creates a small example dataset; it runs by itself once everything is ready.

1. Finding problems with count()

The box above created a tibble called clinic: eight patients, their sex, whether they smoke, and a fasting glucose result in mmol/L. Print it to see what’s inside:

With eight rows you can spot the problems by eye. With 800 you can’t, so you need a tool that shows you every different value in a column. That tool is count(). It counts how many rows have each value:

R treats every distinct spelling as a separate category, so this one column, which ought to have two categories, has four. Nothing has gone wrong in R. The data was recorded inconsistently, and count() has made that visible.

Your turn

Use count() to find out how many different ways smoking status has been recorded.

NoteHint

It’s exactly like clinic |> count(sex), with a different column name.

TipSolution 
clinic |> count(smoker)

Six codes for two answers: Y, Yes and 1 all mean “smoker”; N, No and 0 all mean “non-smoker”.

2. Fixing categories with case_when()

case_when() goes inside mutate() and works through a list of rules, one per line. Each rule has a condition on the left of a tilde, ~, and the value to use on the right. Read the ~ as “then”:

The first rule reads: “if sex is one of "F" or "female", then use "Female"”. %in% asks whether a value appears anywhere in the list that follows. Ending the code with count() checks that the fix worked: two categories, and the counts add up to eight.

Any value that doesn’t match a rule becomes NA (missing). That’s deliberate: if a new spelling turns up, you’ll see an NA in your count() rather than a wrong answer slipping through silently.

Your turn

Recode smoker so that it contains only "Yes" and "No". Fill in the two lists of codes (use the output of Exercise 1, and remember that text values need quotation marks).

NoteHint

The first list needs the three codes that mean “smoker”, each in quotation marks and separated by commas: c("Y", "Yes", "1"). Notice that "1" needs quotation marks too, because the column is text.

TipSolution 
clinic |>
  mutate(
    smoker = case_when(
      smoker %in% c("Y", "Yes", "1") ~ "Yes",
      smoker %in% c("N", "No", "0") ~ "No"
    )
  ) |>
  count(smoker)

3. Missing values, and codes that mean “missing”

Two of the glucose results are -99 and 999. Neither is a possible fasting glucose; in this dataset they are codes that whoever entered the data used to mean “no result”. R can’t know that, so it treats them as real numbers. Look what that does to the mean:

A mean fasting glucose of 117 mmol/L is impossible: a normal value is roughly 4 to 6. (clinic$glucose means “the glucose column of clinic”.) R’s own symbol for a missing value is NA, so the first job is to swap the codes for NA. if_else() does this: if the value is one of the codes, use NA, otherwise keep the value as it is.

Now try the mean again:

The answer is NA. That’s R being careful, not awkward: if some values are unknown, then strictly speaking the mean is unknown too. To get the mean of the values you do have, you have to say so, with na.rm = TRUE (“NA remove: yes”).

Your turn

Calculate the mean glucose of the six patients with a real result.

NoteHint

na.rm is an argument of mean(), so it goes inside the brackets of mean(), after glucose and a comma.

TipSolution 
clinic |> summarise(mean_glucose = mean(glucose, na.rm = TRUE))
WarningRemoving missing values is a decision

na.rm = TRUE means the mean is based on six patients, not eight. That’s usually what you want, but it is a choice, and in a report you should say how many values each result is based on. In session 1 you’ll see why it matters which patients are missing.

4. Changing shape with pivot_longer()

Here are three patients’ systolic blood pressures (mmHg), measured at the start of a study and again after 6 months:

This is wide format: one row per patient, with the timepoints spread across the columns. It’s easy to read, but the timepoint (a variable) is hidden in the column names, and R’s plotting and summary functions can’t get at it there. Long format has one row per patient per timepoint, with the timepoint in a column of its own. pivot_longer() makes the change:

  • cols lists the columns to stack;
  • names_to names the new column that will hold the old column names; and
  • values_to names the new column that will hold the values.

Three patients × two timepoints = six rows.

Your turn

Here are the same three patients’ weights (kg) at baseline, 3 months and 6 months. Turn the table into long format, with a column called timepoint and a column called weight.

NoteHint

cols = c(weight_0m, weight_3m, weight_6m): column names need no quotation marks here, but the new column names after names_to and values_to do, because they don’t exist yet.

TipSolution 
weight_wide |>
  pivot_longer(
    cols = c(weight_0m, weight_3m, weight_6m),
    names_to = "timepoint",
    values_to = "weight"
  )

Before you come in

You’re ready for session 1 if you can:

  • use count() to see every value in a column, and explain why one category can show up as several;
  • use case_when() inside mutate() to recode values, and check the result with count();
  • explain what NA is, why mean() returns NA when a value is missing, and what na.rm = TRUE does; and
  • describe the difference between wide and long data, and use pivot_longer() to turn one into the other.

In the session you’ll use all four on a dataset of 240 patients from a diabetes trial, along with two new functions: clean_names(), which tidies column names, and parse_number(), which rescues numbers that have text stuck to them.
